1. 新增图形验证码服务（复用全局 Redis）
   - 在 `src/auth/` 增加 `CaptchaService`，使用 Node `crypto` 的安全随机数生成固定长度数字验证码和 `randomUUID` 生成 `captchaId`。
   - 将验证码按 `auth:captcha:{captchaId}` 写入 Redis，并通过新增配置 `captcha.expiresIn` 设置秒级过期时间；默认配置放入 `config.yaml`，避免把过期时间散落在业务代码中。
   - 生成 SVG 图形验证码（包含验证码文字及简单干扰线），返回前端可直接用于 `<img src>` 的 `data:image/svg+xml;base64,...`，不引入额外图片库。
   - 提供校验方法：按 `captchaId` 读取验证码，读取不到统一视为错误或已过期；比较时不区分大小写；校验成功后删除 Redis 记录，避免验证码重复使用。

2. 新增验证码接口
   - 在 `AuthController` 增加公开接口 `GET /auth/captcha`，调用 `CaptchaService` 并返回 `{ captchaId, image }`。
   - 保持统一成功响应包装，不改动 JWT Guard；该接口和登录接口都使用 `@Public()`。

3. 扩展登录参数和业务流程
   - 在 `LoginDto` 增加必填 `captchaId`、`captchaCode` 字段及中文基础校验消息。
   - 在 `AuthService.login()` 查询用户和比较密码前调用验证码校验，验证码无效或已过期时直接抛出独立业务错误码及统一文案“验证码错误或已过期”，不查询用户、不执行 bcrypt、不签发 token、不创建会话。
   - 在 `ErrorCodes` 中增加验证码错误码，沿用现有 `AppError` 和统一错误响应机制。
   - Controller 保持只接收 DTO、获取 IP、调用 Service，不把验证码业务逻辑放入 Guard 或 Controller。

4. 补充测试
   - 为 `CaptchaService` 增加单元测试：生成结果结构、Redis key、TTL、无效/过期验证码、大小写校验、成功后删除及重复使用失败。
   - 更新 `AuthService` 单元测试 mock 和登录入参，覆盖验证码成功、错误、过期，以及失败时不访问用户/密码和不创建会话。
   - 更新 `AuthController` 单元测试，验证验证码接口和登录验证码字段透传。
   - 更新 E2E Redis Map mock 及登录辅助方法，覆盖获取验证码、正确登录、错误验证码、过期/不存在验证码和验证码一次性消费。
