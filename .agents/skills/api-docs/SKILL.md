# 接口文档生成

为 NestJS 项目生成/更新面向前端的接口文档（Markdown）。

## 触发信号

- "生成接口文档" / "更新接口文档" / "写接口文档" / "整理接口文档"
- "接口说明" / "接口对接" / "前端联调文档" / "给前端看"
- 用户对接口文档格式提出调整时，按本规范执行

## 输出位置

- **默认生成到项目根目录**：`<项目根>/api-docs.md`
- **用户指定了目录**（如"生成到桌面"、"生成到 docs/xxx"）则生成到指定目录，文件名仍为 `api-docs.md`（除非用户另行指定文件名）
- 文档是独立 .md 文件；若目标目录被 .gitignore 忽略则只存本地不提交

## 文档结构（固定模板）

```markdown
# <项目名> 接口文档

> 前端对接用。Base URL：`http://localhost:3000`
> 初始账号：`...`（如有 seed 账号）

## 一、通用约定

**响应格式**：`{ "code": 0, "message": "ok", "data": {} }`

**判断成败只看 `code`，不要依赖 HTTP 状态码：**

| code | 含义 | 前端处理 |
|---|---|---|
| 0 | 成功 | 用 `data` |
| -1 | 业务错误（如密码错误） | 用 `message` 提示 |
| 401 | 未登录 / 登录已失效 | **清除登录态，跳登录页** |
| 400 | 参数不合法 | 用 `message` 提示 |
| 500 | 服务器错误 | 提示「服务器开小差了」 |

**鉴权**：<项目的鉴权方式一句话>

## 二、接口详情

### 模块一：<模块名>（<controller 前缀>）

> 职责说明。接口前缀：`/xxx`

#### 1. <接口名> `METHOD /path`（鉴权标注）

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|

**请求示例：**

```json
{ }
```

**成功响应：**

| 字段 | 类型 | 说明 |
|---|---|---|

```json
{ }
```

**失败响应：**

| 场景 | 示例 |
|---|---|
| ... | `{ "code": -1, "message": "...", "data": null }` |

## 三、备注

- <单端登录 / token 有效期等前端须知>
```

## 生成步骤

1. **扫描控制器**：`find src -name "*.controller.ts"`（排除 `.spec.ts`/`.e2e-spec.ts`）
2. **提取每个接口**：
   - 方法 + 路径：`@Get/@Post/@Put/@Delete` 等装饰器与 `@Controller('xxx')` 前缀拼接
   - 鉴权：控制器/方法是否有 `@Public()` 装饰器（免鉴权）；无则需登录
   - 请求参数：`@Body()` 的 DTO 字段 + class-validator 校验（IsNotEmpty/IsEmail/MaxLength 等）推导必填与说明；`@Param()` 为路径参数
   - 响应：读取 controller/service 的返回结构；字段含义从实体 `@Column(comment)` 推断
3. **按模块组织**：每个控制器 = 一个模块；模块内接口编号 1、2、3…
4. **生成 markdown**：按上面模板，响应示例用真实字段结构
5. **核对一致性**：对照控制器/DTO/实体确认路径、字段、错误码无误

## 接口格式要点

- 每个接口**必须**有：请求参数字段说明表、请求示例、成功响应（字段说明 + 示例）、失败响应（场景 + 示例）
- 请求参数表：字段/类型/必填/说明（从 DTO 校验推断）
- 失败响应表：列场景 + 完整 JSON（含业务码与 message）
- 鉴权标注用「无需鉴权 / 需鉴权」，不搞花哨排版

## 前端视角原则（重要）

- **只给前端对接需要的信息**：接口路径、参数、返回、错误处理
- **不要包含**：后端内部结构（模块目录、文件职责）、环境搭建/启动步骤、token 实现原理（Redis key、签名算法、刷新机制）、框架细节
- 敏感字段（password 哈希等）标注「前端勿使用，后端后续移除」
- token 机制一句话带过：「收到 401 即视为登录失效，需重新登录」，不解释续期/顶号实现

## 验证

生成后与控制器逐一核对：路径、方法、@Public、DTO 字段、响应结构。有疑问读实际代码确认，不要凭记忆写。
